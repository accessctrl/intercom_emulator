Quick checks when websocket is not connecting:
- Start with `--dart-define-from-file=.secrets.local.json` so `HUB_KEY` is loaded.
- Ensure `EMU_FAMILY` + `EMU_SERIAL` exactly match an active staging hub/controller identity.
- If server logs show many `GET /... 404`, it is usually bot traffic and is unrelated to `/api/cloud/hub/ws`.

Flutter Android emulator for IGC intercom backend protocol.

## Goals

- Use only real staging backend protocol (`https://staging.igcsolutions.org`)
- No mock backend
- Explicitly surface server capability gaps for full intercom call flow

## Current implementation

- HMAC-authenticated websocket client for `/api/cloud/hub/ws`
- Periodic `status` heartbeats
- Command intake (`command`, `command_batch`)
- Command result reporting (`command_results`)
- Saved connection settings (SharedPreferences)
- Runtime logs and session diagnostics UI

## Important limitation

This emulator currently reports low-level tunnel commands as `unsupported` because
the backend does not yet expose complete mobile-intercom runtime APIs for:

- app-level incoming call signaling
- WebRTC SDP/ICE call negotiation
- call lifecycle (accept/decline/hangup)
- in-call door-open control contract

See [docs/server-capability-gap.md](docs/server-capability-gap.md).

## Run

1. Install dependencies:

	```bash
	flutter pub get
	```

2. Run on Android device/emulator:

	```bash
	flutter run -d RZCT90SSQLX --dart-define-from-file=.secrets.local.json
	```

2.1. No manual input mode (recommended):

	```bash
	flutter run -d RZCT90SSQLX --dart-define-from-file=.secrets.local.json
	```

	Setup once:
	- Copy `.secrets.example.json` to `.secrets.local.json`
	- Put real `HUB_KEY` value into `.secrets.local.json`
	- `.secrets.local.json` is gitignored

3. In app settings, configure:
	- Base URL (`https://staging.igcsolutions.org`)
	- Family/Serial for registered staging hub identity
	- Hub key is not entered in UI; it is taken from `.secrets.local.json`

### What is Hub key?

- `Hub key` is the shared secret used for HMAC auth in `/api/cloud/hub/ws`.
- Signature format on server: `HMAC_SHA256(hub_key, "${ts}.${nonce}.${JSON.stringify(body)}")`.
- This key must match exactly what backend has for that hub identity (or global `CLOUD_HUB_DEFAULT_KEY`).
- In no-manual-input mode, pass it through `.secrets.local.json` with `--dart-define-from-file`.

### About serial format

- `serial` is not generated by emulator and is not forced to `emu-001`.
- Use your real naming convention, for example `igci000001`, if that is how your environment is managed.
- Emulator only sends the identity you input (`family + serial`), and backend decides ownership/authentication.

## Important for real IGCH devices

- Do not reuse the same `family + serial + key` as your active physical IGCH hub.
- Backend gateway keeps a single active websocket session per hub identity. If emulator uses the same identity, it can replace the real hub session.
- Use a dedicated staging-only emulator identity (separate serial/key).
